# 観測台帳

「今日の美瑛」のスコア(予測)と、実際の見え方(目撃情報)を突き合わせるための台帳です。
スコアの係数はこの記録を根拠に調整します — [スコアの仕組み](../logic.html)に書いた「外れたら直す」の実体がこのファイルです。

## observations.csv の列

| 列 | 値 | 説明 |
|---|---|---|
| 日付 | YYYY-MM-DD | 観測日 |
| 池の色 | 青 / 微妙 / 白濁 / (空欄) | 実際の青い池の色。不明なら空欄 |
| 霧 | 出た / 薄い / なし / (空欄) | その朝、丘に霧・雲海が出たか。不明なら空欄 |
| 池スコア | 0-100 | その日にサイトが出していた青い池スコア |
| 霧スコア | 0-100 | その朝のサイトの霧・雲海チャンス |
| スコア出典 | 当日予報 / 事後推定 | 下記参照。空欄はスコアを記録していない行 |
| 情報源 | 現地 / IG / DM / SNS / カメラ | 目撃情報の出どころ |
| メモ | 自由記述 | 例: 雨後3日目、雲海は下富良野側のみ 等 |

### スコア出典について

台帳の目的は**予報**の較正なので、スコアは「その朝サイトが実際に出していた値」で
なければ意味がありません。

- **当日予報** — `forecast-log.jsonl`(下記)に残したその朝の予報から計算した値。これが本来あるべき形
- **事後推定** — 後日 Open-Meteo の実測・再解析値から計算し直した値。予報が外れた日は
  サイトが表示していた値とズレるため、**「予報が外れた」のか「係数が悪い」のかを区別できません**

2026-08-31 に予報ロガーを入れる前の行はすべて事後推定です。係数を調整するときは
当日予報の行だけを根拠にしてください。

## forecast-log.jsonl

毎朝 05:10 JST に、サイトと同じ問い合わせで取得した予報を1日1行ずつ貯めています
(`scripts/log_forecast.py`)。Open-Meteo のアーカイブAPIが返すのは実測・再解析値で、
「その日の朝に出ていた予報」は後から取れないため、消えないうちに残しておくものです。

**スコアではなく入力(hourly)を残しています。** 計算式は app.js の1箇所にあるままでよく、
「直近48時間の雨」のような窓の取り方を後で見直しても全期間を計算し直せるためです
(7/16の深夜の雨が窓から漏れた件がまさにこれ)。

各行は対象日の前2日〜翌1日の96時間ぶん。`start` からの1時間刻みで、値は並びで入っています。

| キー | 内容 |
|---|---|
| date | 対象日(JST) |
| fetched_at | 取得時刻(UTC) |
| start / hours | 値の並びの開始時刻(JST)と本数 |
| cloud_cover ほか | app.js と同じ6変数の hourly 値 |

## 運用方針

- **全日埋める必要はありません。** まばらでも、件数が貯まれば係数調整の根拠になります
- **スコアが極端な日(80以上 / 25以下)を優先して確認**します。的中検証として最も情報量が多いのがこの両端です
- 目撃情報の提供は Instagram [@biei_explorer](https://www.instagram.com/biei_explorer/) のDMで歓迎しています
